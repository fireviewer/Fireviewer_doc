# Statuts et vocabulaire

Pour éviter les présentations trompeuses, ce pack utilise les statuts suivants :

- **documenté** : décrit dans une source de référence ;
- **implémenté** : présent dans le code ;
- **construit/testé** : une commande ou un test identifié a été exécuté dans un périmètre donné ;
- **déployé** : présent sur une infrastructure identifiée ;
- **accepté** : un parcours ou livrable a passé ses critères de réception ;
- **qualifié** : un résultat a passé une procédure d'évaluation explicite pour l'usage annoncé ;
- **expérimental / recherche** : conservé pour essais ou comparaison, sans revendication opérationnelle ;
- **transitoire** : maintenu pour compatibilité en attendant migration de consommateurs ;
- **historique / archive** : conservé pour provenance ou reproductibilité, pas pour nouveau développement ;
- **en attente** : volontairement hors travaux actuels ;
- **incomplet** : publication ou intégration ne disposant pas encore des éléments minimaux annoncés.

## Classes d'information incendie

Toujours distinguer :

1. fait établi ;
2. observation ;
3. donnée externe ;
4. résultat IA ;
5. hypothèse géographique ;
6. calcul FireViewer ;
7. estimation ;
8. décision humaine ;
9. information non vérifiée.

Une détection visuelle n'est pas une coordonnée. Une reconstruction n'est pas une observation. Une simulation n'est pas une preuve d'un événement réel. Une absence de détection ne prouve pas l'absence de feu.
